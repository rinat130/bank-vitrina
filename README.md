# Банковская витрина — стартовый сайт

Это готовый статический сайт. **Нет сервера, базы данных, платных пакетов и сборки.**

## Что лежит внутри

- `index.html` — страница сайта;
- `styles.css` — весь дизайн;
- `script.js` — вкладки, поиск и отображение карточек;
- `data/offers.json` — карточки банковских офферов;
- `.pages.yml` — поля админки Pages CMS;
- `media/` — логотипы, которые загрузит Pages CMS.

## Самый простой запуск

1. Войдите в https://github.com и создайте репозиторий `bank-vitrina` (Create repository). Для начала можно сделать публичный. Никаких паролей, токенов и секретов в него не загружайте.
2. В репозитории выберите **Add file → Upload files**. Распакуйте ZIP на компьютере и загрузите **содержимое папки** в корень репозитория, не одну ZIP-архивную папку. Убедитесь, что `.pages.yml` (файл с точкой в начале) и `index.html` лежат в корне, а `data/offers.json` — в папке `data`.
3. Откройте https://dash.cloudflare.com, войдите и перейдите в **Workers & Pages → Create application → Pages → Connect to Git / Import existing Git repository**. Укажите GitHub и выберите репозиторий.
4. Production branch: `main`; framework: None / без фреймворка; build command: `exit 0`; output directory: `.`. Нажмите Deploy. Ваша ссылка будет вида `bank-vitrina.pages.dev`.
5. Откройте https://app.pagescms.org, войдите через GitHub, разрешите Pages CMS доступ к репозиторию. Откройте репозиторий и пункт **Банковские офферы**. Файл `.pages.yml` уже настроен.
6. Замените демо-офферы настоящими и сохраните. Pages CMS обновит файл в GitHub; Cloudflare автоматически опубликует изменения.

## Где что менять

- **Банк, название, категория, надпись, условия, логотип, партнёрская ссылка, видимость** — через Pages CMS → «Банковские офферы».
- **Название сайта «выбор.» и крупные тексты на главной** — пока в `index.html` (можно попросить ИИ отредактировать).
- **Цвета и стиль** — `styles.css`, в начале есть переменные цветов `:root`.
- **Добавить новую категорию** — изменить `index.html`, `script.js` и `.pages.yml`; для первой версии лучше пользоваться готовыми.

**Важно:** все исходные офферы вымышлены и кнопки без ссылок отключены. При публикации финансовых предложений в РФ нужно проверить актуальность ставок и обязательную информацию, а также законодательные требования к рекламе, маркировке и обработке данных.

### Проблемы

- На сайте не отображаются карточки при открытии `index.html` двойным кликом? Это ожидаемо: браузер может блокировать чтение JSON в режиме `file://`. Смотрите сайт по адресу `*.pages.dev` после публикации или запустите локальный сервер.
- Не отображается админка? Проверьте наличие `.pages.yml` в корне и разрешение Pages CMS на нужный GitHub-репозиторий.
- После сохранения изменения не сразу видны? Посмотрите в Cloudflare вкладку Deployments: GitHub-коммит запускает новую публикацию.


## Важно для аудитории из России: Cloudflare не всегда доступен

Cloudflare официально сообщает об ограничениях доступа из России. Поэтому Cloudflare Pages можно использовать **для теста**, но перед привлечением трафика из РФ проверяйте открытие сайта через российские мобильные и домашние сети. Для надёжного доступа можно разместить точно те же файлы на российском хостинге.

### Бесплатный хостинг Beget — альтернативная публикация в России

У Beget есть FreeHosting для одного небольшого сайта. Без платной подписки, но с ограничениями и без техподдержки: https://beget.com/ru/hosting/free. Возможность использования под ваш коммерческий проект проверьте в актуальных условиях Beget.

1. Зарегистрируйтесь на Beget FreeHosting и создайте сайт. Он получит технический адрес.
2. В Beget откройте **FTP-аккаунты**. Узнайте FTP-хост, логин, пароль и путь к папке `public_html` созданного сайта относительно корня FTP-доступа. Если тариф позволяет, безопаснее выделить отдельный FTP-аккаунт только для папки сайта. Используйте **FTP через TLS / FTPS**, на бесплатном Beget это обязательно.
3. В GitHub → ваш репозиторий → **Settings → Secrets and variables → Actions → Secrets** добавьте три секрета: `FTP_HOST` (адрес сервера из Beget), `FTP_USER` (логин выделенного FTP-аккаунта), `FTP_PASSWORD` (его пароль). **Никогда не записывайте пароли в код.**
4. Там же откройте вкладку **Variables**. Создайте `RU_SITE_DIR` — путь к папке сайта от корня FTP, обязательно со слешем в конце, например `./mysite.beget.tech/public_html/` (**точный путь смотрите в Beget, пример не универсален**). Затем включите публикацию переменной `RU_HOSTING_ENABLED` со значением `true`.
5. GitHub → **Actions → Publish to Russian hosting → Run workflow** — опубликует файлы. Дальше каждое сохранение оффера в Pages CMS автоматически меняет GitHub и запускает публикацию на Beget. Настройка уже включена в шаблон `.github/workflows/beget-deploy.yml`.
6. Проверьте технический адрес в российской сети. Домен можно купить и подключить потом.

Если возникнет ошибка `FTPS` или `550`, проверьте адрес сервера, порт, логин и настройку отдельного FTP-аккаунта на папку `public_html`. Переменная `RU_SITE_DIR` должна указывать **именно** на `public_html` нужного сайта, а не на корень всего аккаунта Beget. Не включайте `RU_HOSTING_ENABLED`, пока FTP-путь не настроен.

Для первого тестирования достаточно одного бесплатного способа публикации. Одновременно запускать Cloudflare и Beget не требуется.
